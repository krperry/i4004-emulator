Lesson 3: Adding Like a Calculator

The 4004 was designed for one job: to be the brain of a desk calculator. In this lesson you will walk through examples/bcd_add.asm, a program that does exactly what that calculator did. It adds two 8-digit numbers in decimal, one digit at a time, and prints the answer. Along the way you meet RAM, subroutines, counting loops, and DAA, the instruction that makes decimal adding work.

Topics covered in this lesson

  • Binary coded decimal, or BCD, and why calculators use it
  • Storing digits in RAM, and choosing a RAM bank with DCL
  • Calling a subroutine with JMS and returning with BBL
  • A counting loop with ISZ
  • Adding with carry using ADM, then fixing the answer with DAA
  • Turning a digit into a printable character

This lesson builds on the last one. If you have not done Hello, World on a 4-Bit Chip yet, do that first.

What the Program Does

Run it:

python -m i4004 run examples/bcd_add.asm --console --accessible

The first line you hear is:

Output: 058598744

The program added 27,182,818 and 31,415,926. The answer is 58,598,744. It printed 9 digits, not 8, because adding two 8-digit numbers can give a 9-digit answer. Here that extra digit is 0.

After the output, the emulator reports what is left in RAM. Listen for these two lines:

RAM bank 0, chip 0, register 0. Characters: 4, 4, 7, 8, 9, 5, 8, 5,
then 8 zeros.
RAM bank 0, chip 0, register 1. Characters: 6, 2, 9, 5, 1, 4, 1, 3,
then 8 zeros.

Register 0 holds the answer, and register 1 still holds the second number. Read register 0 backwards and you get 5, 8, 5, 9, 8, 7, 4, 4, which is the answer. The next section explains why it is stored backwards.

Binary Coded Decimal

A calculator shows decimal digits, 0 to 9. One easy way to store a decimal number is to keep each digit in its own nibble. This is called binary coded decimal, or BCD. The number 2,718 is stored as four nibbles: 2, 7, 1 and 8. A nibble can hold up to 15, but in BCD only 0 to 9 are used.

BCD suits the 4004 perfectly. One nibble is one digit, and one RAM character is one nibble. A RAM register has 16 characters, so it can hold a 16-digit number. The Busicom calculator kept its numbers exactly like this.

The program stores the lowest digit first, in character 0. That is because you add numbers starting from the right, the ones column, and carry to the left. Storing the ones digit first means the program can start at character 0 and simply count up.

Here is the plan for RAM. Everything is in bank 0, chip 0:

How the program uses RAM
RAM registerHolds SRC address of character 0
0The first number, A. The answer is written over it. Character 8 gets the final carry.hex 00
1The second number, Bhex 10

Remember from Lesson 1 that the low nibble of an SRC address picks the character, and the two bits above it pick the RAM register. So hex 00 is register 0, character 0, and hex 10 is register 1, character 0.

The program is 88 bytes and takes 400 instruction cycles, about 4.3 thousandths of a second on a real 4004. It has five parts: pick the RAM bank, load the two numbers, add them, print the answer, and a subroutine that does the loading. The subroutine is at the end of the program, but it runs during part 2, so it is explained there.

Part 1: Choosing a RAM Bank

Address 000: LDM 0

Byte: hex D0. D means LDM, load immediate, and 0 is the value. The accumulator becomes 0.

Address 001: DCL

Byte: hex FD.

DCL means designate command line. It picks the RAM bank from the value in the accumulator, so this picks bank 0. A DCL instruction has no operand of its own. That is why the bank number had to be loaded into the accumulator first. Many 4004 instructions work this way, using the accumulator as their input.

Bank 0 is already selected when the chip starts, so strictly these two lines are not needed. Good programs set it anyway, so they do not depend on what happened before.

Part 2: Loading the Two Numbers

The two numbers are stored in ROM, at the labels numA and numB. The calculation has to happen in RAM, so first the program copies each number from ROM into RAM. Both copies do the same job, so the program uses one subroutine called load8 for both. It sets up two pointers, then calls the subroutine.

Address 002: FIM P0, numA

Bytes: hex 20, then hex 48.

This puts the ROM address of the first number, hex 048, into pair P0. Only the low 8 bits fit, but that is fine, because FIN reads from the current page anyway. P0 is the ROM pointer. As in the last lesson, it has to be P0, because FIN always uses P0.

Address 004: FIM P1, 0x00

Bytes: hex 22, then hex 00.

This puts hex 00 into pair P1. P1 is the RAM pointer, and hex 00 means RAM register 0, character 0. That is where the first number goes.

Address 006: JMS load8

Bytes: hex 50, then hex 3B.

JMS means jump to subroutine. The 5 means JMS, and the next three hex digits, 0, 3 and B, are the address of load8. Before it jumps, the chip saves the address of the next instruction, hex 008, so it knows where to come back to.

The 4004 keeps these return addresses inside the chip, in a stack with room for only three of them. A subroutine can call another subroutine, and that one can call a third, but no deeper. If a program goes one level deeper, the oldest return address is lost. The emulator copies that behaviour exactly.

Now jump ahead to the subroutine, which runs next.

Address 03B: load8: LDM 8

Byte: hex D8. The accumulator becomes 8.

Address 03C: XCH R6

Byte: hex B6.

XCH means exchange. It swaps the accumulator with R6, so R6 becomes 8. R6 is the loop counter. There is no instruction that loads a number straight into a single register, so LDM followed by XCH is the usual way to do it.

Why 8, when the loop should run 8 times? The loop is counted by ISZ, which counts up and stops when the register wraps round to 0. Starting at 8, the counter goes 9, 10, 11, 12, 13, 14, 15, and then 0. That is 8 steps. To loop some number of times, start the counter at 16 minus that number.

Address 03D: ldlp: FIN P5

Byte: hex 3A.

This reads the ROM byte that P0 points at, and puts it in pair P5, which is R10 and R11. The first time round, P0 is hex 48, and the byte there is hex 08, the lowest digit of 27,182,818. So R10 becomes 0 and R11 becomes 8. The digit is in R11.

Address 03E: SRC P1

Byte: hex 23.

This sends the RAM address in P1, so the next RAM instruction will use register 0, character 0.

Address 03F: LD R11

Byte: hex AB. This copies the digit from R11 into the accumulator.

Address 040: WRM

Byte: hex E0.

WRM means write memory. It writes the accumulator into the RAM character chosen by the last SRC. The digit 8 is now in RAM.

Address 041: ISZ R1, nowrap

Bytes: hex 71, then hex 44.

This moves the ROM pointer on to the next digit, by adding 1 to R1. If R1 did not wrap round to 0, it jumps to nowrap and skips the next line. This is the same two-register counting trick you saw in the last lesson.

Address 043: INC R0

Byte: hex 60.

The program only gets here if R1 wrapped from 15 to 0, so it carries 1 into R0. The first number starts at hex 48, so this happens on the eighth digit, when the pointer goes from hex 4F to hex 50.

A real bug. The first version of this program did not have this ISZ and INC pair. It just used INC R1. It printed nonsense. In that version the second number started at hex 4E, so after two digits its pointer went from hex 4F back to hex 40, not on to hex 50, and read the wrong bytes. The fix is these two lines. Bugs like this, where a value quietly wraps round, are very common on small chips. When something goes wrong, a trace is the best way to find it.

Address 044: nowrap: INC R3

Byte: hex 63.

This moves the RAM pointer on to the next character, by adding 1 to R3, the low nibble of P1. There is no wrap to worry about, because it only goes from 0 to 8.

Address 045: ISZ R6, ldlp

Bytes: hex 76, then hex 3D.

This counts the loop. It adds 1 to R6, and jumps back to ldlp unless R6 wrapped to 0. After 8 digits, R6 wraps and the loop ends.

Address 047: BBL 0

Byte: hex C0.

BBL means branch back and load. It returns from the subroutine, to the address saved by JMS, which is hex 008. It also loads its operand, here 0, into the accumulator. Subroutines often used that value to report success or failure. This one does not need to, so it returns 0.

Addresses 008 to 00C: the second number

Back in the main program, these three lines do the same thing again for the second number:

008  20 50   FIM  P0, numB
00A  22 10   FIM  P1, 0x10
00C  50 3B   JMS  load8

The ROM pointer is now numB, hex 050. The RAM pointer is hex 10, which is RAM register 1, character 0. Then the same subroutine copies it in. This time the subroutine returns to hex 00E. Reusing one piece of code with different pointers is exactly what subroutines are for.

Part 3: Adding the Numbers

Address 00E: CLC

Byte: hex F1.

CLC means clear carry. The first column of an addition has nothing carried into it, so the carry must start at 0.

Address 00F: FIM P1, 0x00

Bytes: hex 22, then hex 00. P1 points at RAM register 0, character 0. That is the first number, which is also where the answer will go.

Address 011: FIM P2, 0x10

Bytes: hex 24, then hex 10. P2 points at RAM register 1, character 0, the second number.

Addresses 013 and 014: LDM 8, then XCH R6

Bytes: hex D8, then hex B6. As before, this sets R6 to 8 so the loop runs 8 times, once for each digit.

Address 015: addlp: SRC P2

Byte: hex 25. This selects the current digit of the second number.

Address 016: RDM

Byte: hex E9.

RDM means read memory. It reads the selected RAM character into the accumulator. The first time round, that is 6, the lowest digit of 31,415,926.

Address 017: SRC P1

Byte: hex 23. This selects the matching digit of the first number.

Address 018: ADM

Byte: hex EB.

ADM means add memory. It adds the selected RAM character and the carry to the accumulator. The first time round, that is 6, plus 8, plus a carry of 0, which makes 14.

But 14 is not a decimal digit. The answer should be 4, carry 1. The chip added in binary, where a nibble can go up to 15. The next instruction fixes that.

Address 019: DAA

Byte: hex FB.

DAA means decimal adjust accumulator. If the accumulator is more than 9, or the carry is already 1, it adds 6. If that addition goes past 15, it sets the carry.

Why 6? A nibble counts to 16 before it carries, but a decimal digit should carry at 10. The difference is 6. Adding 6 pushes the value past 15, so the real carry happens, and leaves the right digit behind. For our example, 14 plus 6 is 20. That is 16 plus 4, so the accumulator becomes 4 and the carry becomes 1. That is exactly 14 written in decimal: carry 1, digit 4.

It works when ADM itself carried, too. For example, 9 plus 9 is 18. ADM leaves 2 with carry 1. DAA sees the carry, adds 6, and gets 8 with the carry still 1. That is 18 in decimal.

One unusual detail: DAA never clears the carry. If the carry was already 1, it stays 1. That is what the 9 plus 9 case needs.

Address 01A: WRM

Byte: hex E0. This writes the corrected digit back into the selected character. The selection is still the first number, so the answer replaces it, one digit at a time.

Addresses 01B and 01C: INC R3, then INC R5

Bytes: hex 63, then hex 65. These move both RAM pointers on to the next character. INC does not change the carry. That matters, because the carry from this digit has to survive until the next ADM.

Address 01D: ISZ R6, addlp

Bytes: hex 76, then hex 15. Count the loop, and go back to addlp for the next digit until all 8 are done. ISZ does not change the carry either.

Addresses 01F to 021: storing the last carry

01F  23   SRC  P1
020  F7   TCC
021  E0   WRM

After 8 digits there may be a carry left over. With 99,999,999 plus 1, for example, the answer needs a ninth digit.

R3 has been counted up to 8, so SRC P1 now selects character 8 of register 0. TCC means transmit carry and clear. It puts the carry, 0 or 1, into the accumulator, and clears the carry. Then WRM writes it into character 8. In our example there is no final carry, so character 8 is 0. That is the leading zero in 058598744.

Hearing the add loop

Run the program with a trace and listen to the first time round the add loop. It starts at step 133. Use your screen reader's find command to search for "Step 133".

python -m i4004 run examples/bcd_add.asm --console --accessible --trace --quiet

Step 134, at hex 016: RDM. Read the selected RAM character into the
accumulator. Result: accumulator now 6.
Step 135, at hex 017: SRC P1. Send register pair 1 as the RAM and ROM
port address. Result: selected address now hex 00.
Step 136, at hex 018: ADM. Add the selected RAM character and the carry

Step 137, at hex 019: DAA. Decimal adjust the accumulator. Result:

On the next time round, the digits are 2 and 1. With the carry, that makes 4. ADM uses up the carry, so the carry becomes 0. Then DAA reports no change, because 4 is already a good decimal digit.

Part 4: Printing the Answer

The answer has to be printed from the highest digit down, character 8 to character 0. Each digit is a number from 0 to 9. To print it, the program turns it into the ASCII character for that digit. The ASCII characters 0 to 9 are hex 30 to hex 39. So the high nibble is always 3, and the low nibble is the digit itself. Nothing needs to be added or calculated.

Address 022: FIM P4, 0x00

Bytes: hex 28, then hex 00. P4, which is R8 and R9, will be the SRC address for the console, ROM port 0.

Addresses 024 and 025: LDM 7, then XCH R7

Bytes: hex D7, then hex B7. R7 is the loop counter. There are 9 digits to print, and 16 minus 9 is 7.

Addresses 026 and 027: LDM 8, then XCH R3

Bytes: hex D8, then hex B3. This sets R3 to 8, so P1 points at character 8 of register 0, the highest digit.

Address 028: prlp: SRC P1

Byte: hex 23. This selects the current answer digit in RAM.

Address 029: RDM

Byte: hex E9. This reads the digit into the accumulator.

Address 02A: XCH R10

Byte: hex BA.

This saves the digit in R10. The accumulator is about to be needed for the 3, so the digit has to wait somewhere else. R10 is free now that the loading is finished.

Address 02B: SRC P4

Byte: hex 29. This selects ROM port 0, the console.

A single SRC address chooses the RAM character and the ROM port at the same time. The program switches between P1 for RAM and P4 for the console. In this program, P1's high nibble is also 0, so SRC P1 would happen to pick port 0 as well. But if the answer were in RAM register 1, P1 would hold hex 1 something, and the output would go to port 1 instead. Using a separate pair for the port makes the program say what it means, and keeps it working if the RAM layout changes.

Addresses 02C and 02D: LDM 3, then WRR

Bytes: hex D3, then hex E2. This sends the high nibble, 3.

Addresses 02E and 02F: LD R10, then WRR

Bytes: hex AA, then hex E2. This sends the digit as the low nibble. The console joins 3 and the digit, and prints a character from 0 to 9.

Addresses 030 to 032: LD R3, DAC, XCH R3

030  A3   LD   R3
031  F8   DAC
032  B3   XCH  R3

The 4004 can add 1 to a register with INC, but it has no instruction to take 1 away from one. So the program copies R3 into the accumulator, uses DAC, decrement accumulator, and then swaps the result back into R3. This moves the pointer down one character.

Address 033: ISZ R7, prlp

Bytes: hex 77, then hex 28. This counts the loop, and goes back for the next digit until all 9 are printed.

Addresses 035 to 038: the new line

035  D0   LDM  0
036  E2   WRR
037  DA   LDM  10
038  E2   WRR

This sends 0 and then 10, which is hex 0A, the new line character. The last SRC was P4, so it still goes to the console.

Address 039: done: JUN done

Bytes: hex 40, then hex 39. This is the jump to itself that parks the chip, just like in the hello program.

Part 5: The Numbers

Address 048: numA: DB 8,1,8,2,8,1,7,2

This is the first number, 27,182,818, written lowest digit first, so it reads backwards. Each digit takes a whole byte, even though it only needs a nibble. That keeps the loading loop simple, because FIN reads a byte, and the digit just lands in the low register, R11.

Address 050: numB: DB 6,2,9,5,1,4,1,3

This is the second number, 31,415,926, also written backwards.

You may have noticed the two numbers. 27,182,818 is the start of the number e, and 31,415,926 is the start of pi.

Summary

  • BCD keeps one decimal digit per nibble. That is how the 4004's calculators stored numbers.
  • Digits are stored lowest first, so adding can start at character 0 and count up.
  • DCL picks a RAM bank. SRC picks the character. RDM and WRM read and write it.
  • JMS calls a subroutine and BBL returns. The chip only remembers three return addresses.
  • To loop some number of times with ISZ, start the counter at 16 minus that number.
  • ADM adds in binary. DAA then adds 6 when needed to turn the result into a decimal digit and a carry.
  • A digit d prints as the ASCII character hex 3d, so the program sends 3 and then the digit.

Exercises

  1. Change the numbers so the program adds 99,999,999 and 1. Remember to write the digits backwards. What does it print? Which line put the 1 at the front?
  2. Delete the DAA line and run the program. Some of the printed characters are no longer digits. Work out why. Hint: what ASCII character is hex 3E?
  3. Count the instruction cycles for one time round the add loop, from addlp to ISZ R6, addlp. Remember that ISZ is a two-byte instruction. How long is that on a real 4004?
  4. Change the program so the answer goes into RAM register 2, and both original numbers are kept. You will need a third pointer. Which register pairs are still free?
  5. Harder: make the program skip the leading zero, so it prints 58598744. Hint: before the print loop, read character 8 and decide where to start.
