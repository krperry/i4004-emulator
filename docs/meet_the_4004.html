Lesson 1: Meet the 4004

Before you can read a 4004 program you need to know what the chip has inside it to work with. This lesson is a short tour. Nothing here needs to be memorised. You can come back to it while you read the other lessons.

Topics covered in this lesson

  • Bits, nibbles and hexadecimal
  • The accumulator and the carry
  • The 16 registers and the 8 register pairs
  • Program memory, called ROM, and its pages
  • Data memory, called RAM
  • Input and output ports
  • How one line of assembly becomes bytes
  • Running the assembler and reading a listing

Bits, Nibbles and Hexadecimal

A bit is a single 0 or 1. Four bits together are called a nibble. A nibble can hold 16 different values, from 0 to 15. The 4004 is a 4-bit chip, which means almost everything it does, it does one nibble at a time.

Programmers usually write nibbles in hexadecimal, or hex for short. Hex counts to 15 using one symbol per value. It uses 0 to 9 like normal, then A for 10, B for 11, C for 12, D for 13, E for 14 and F for 15. So one hex digit is exactly one nibble. That is why hex is so handy here.

Two nibbles make a byte, which is written as two hex digits. For example, the byte hex 48 has a high nibble of 4 and a low nibble of 8. As a normal number it is 4 times 16, plus 8, which is 72. In the assembly code, hex numbers are written with 0x in front, as in 0x48. The emulator's accessible output says hex 48 instead.

The Accumulator and the Carry

The accumulator is the chip's main working nibble. Almost every calculation goes through it. You load a value into the accumulator, do something to it, and store the answer somewhere else.

The carry is a single bit that sits beside the accumulator. When an addition goes past 15, the extra 1 goes into the carry, just as you carry a 1 when you add numbers on paper. For example, 9 plus 8 is 17. The accumulator can only hold 0 to 15, so it keeps 1 and the carry becomes 1. Together they mean 16 plus 1.

The 16 Registers and the 8 Pairs

Besides the accumulator, the 4004 has 16 registers, named R0 to R15. Each one holds one nibble. Think of them as 16 small boxes for keeping values close at hand.

Some jobs need a whole byte, such as a memory address. For those, the registers are grouped into 8 register pairs, named P0 to P7. Pair P0 is R0 and R1, pair P1 is R2 and R3, and so on up to P7, which is R14 and R15. In a pair, the even register holds the high nibble and the odd register holds the low nibble. So if R0 is 1 and R1 is 7, pair P0 holds the byte hex 17.

Program Memory, or ROM

The program itself lives in ROM, which stands for read-only memory. On a real system this was a set of Intel 4001 chips. The 4004 can reach 4,096 bytes of ROM, at addresses hex 000 to hex FFF.

The chip keeps the address of the next instruction in its program counter. It reads the byte there, does what it says, and moves on to the next one.

ROM is divided into pages of 256 bytes each. Page 0 is hex 000 to hex 0FF, page 1 is hex 100 to hex 1FF, and so on. Pages matter because some instructions only have room for an 8-bit address. Those instructions can only jump, or read data, inside the current page. Both example programs fit in page 0, so you will not have to think about this much yet.

Data Memory, or RAM

Values the program needs to change are kept in RAM, which was a set of Intel 4002 chips. The RAM is organised in levels, a bit like a street address:

  • A bank. There are up to 8 banks. The DCL instruction picks which bank to use.
  • A chip inside the bank, from 0 to 3.
  • A register inside the chip, from 0 to 3. RAM registers are not the same as the 16 CPU registers. They are just rows of memory.
  • A character inside the RAM register, from 0 to 15. Each character holds one nibble. A RAM register also has 4 extra status characters, which programs used for things like signs and decimal points.

The 4004 does not put a RAM address inside each instruction. Instead you first send an address with the SRC instruction, short for send register control. Then the RAM instructions, such as RDM to read and WRM to write, use the address you sent. The address is one byte from a register pair. The top 2 bits pick the chip, the next 2 bits pick the register, and the low nibble picks the character.

Input and Output Ports

The chip talks to the outside world, such as keyboards, printers and lights, through 4-bit ports. Each ROM chip has a port, and each RAM chip has an output port. SRC picks the port too. For a ROM port, the high nibble of the SRC address is the port number. WRR writes the accumulator to that ROM port, and RDR reads from it.

A real 4004 had no screen. To let the example programs print text, the emulator can pretend a ROM port is wired to a terminal. You turn this on with the --console option. The next lesson explains exactly how a 4-bit port can print letters.

How One Line of Assembly Becomes Bytes

The chip only understands numbers. Assembly language gives each instruction a short name, called a mnemonic, so people can read it. The assembler turns each line into the numbers the chip runs, which are called machine code.

Here is a simple example. This line loads the value 5 into the accumulator:

LDM 5

It becomes one byte, hex D5. The high nibble, D, means load immediate, which is LDM. The low nibble, 5, is the value. Most 4004 instructions follow this idea. The high nibble says what to do, and the low nibble says which register or what value.

Some instructions need more room, such as a jump to a 12-bit address. Those take two bytes. For example, JUN 0x123 becomes hex 41 then hex 23. The 4 means jump unconditional, and the remaining three hex digits, 1, 2 and 3, are the address.

A program line can also have three other things:

  • A label at the start, ending in a colon, such as loop:. A label names an address so you can jump to it without working out the number yourself.
  • A comment, starting with a semicolon. Everything after the semicolon is ignored by the assembler. It is there for people.
  • A directive, which is an instruction to the assembler, not to the chip. ORG 0 means start putting code at address 0. DB means put these data bytes here.

Each one-byte instruction takes the real chip one instruction cycle, which is 10.8 millionths of a second. Two-byte instructions take two cycles. The emulator counts cycles and tells you how long a program would have taken on the real chip.

Running the Assembler

You can ask the assembler for a listing, which shows every source line with its address and bytes. Try it:

python -m i4004 asm examples/hello.asm --listing --accessible

Lines sound like this:

Line 8, hex 000, bytes 22 00: start: FIM P1, 0x00

That means source line 8 was placed at address hex 000 and became the two bytes hex 22 and hex 00. The assembler also writes the bytes to a file called examples/hello.bin. That file is the program exactly as it would be burned into a ROM chip.

You can go the other way too. The disassembler reads bytes and turns them back into assembly with a description of each instruction:

python -m i4004 disasm examples/hello.bin --accessible

Summary

  • A nibble is 4 bits and holds 0 to 15. One hex digit is one nibble.
  • The accumulator is the chip's main working nibble. The carry catches anything past 15.
  • There are 16 registers, R0 to R15, grouped into 8 pairs, P0 to P7.
  • Programs live in ROM, which is split into 256-byte pages.
  • Data lives in RAM, addressed by bank, chip, register and character. You pick the address with SRC first.
  • Ports connect the chip to the world, also chosen with SRC.
  • The assembler turns each line into one or two bytes. A listing shows you which bytes.
