4004 Instruction Reference

This page lists every instruction the Intel 4004 understands, 46 in all. It starts with tables you can scan quickly, then gives each instruction its own section with the details. Use your screen reader's heading key to jump between instructions. Each instruction section is a level 3 heading that starts with the mnemonic, so you can also use your find command to search for a name such as ISZ:.

How to Read This Page

These short names are used throughout:

  • A is the accumulator. C is the carry bit.
  • Rr is one of the 16 registers, R0 to R15. In the bytes, r is its number as one hex digit, 0 to F.
  • Pp is one of the 8 register pairs, P0 to P7. Pair p is made of registers 2p and 2p plus 1. For example, P3 is R6 and R7.
  • d is a 4-bit value, 0 to 15, written into the instruction itself.
  • The selected RAM character means the one chosen by the last SRC and DCL. The selected port means the port chosen by the last SRC.
  • Cycles are instruction cycles. One cycle is 8 clock ticks, which is 10.8 millionths of a second on a 740 kilohertz 4004.

A two-byte instruction is shown as two bytes separated by a space, such as 4a aa. In that example, the first byte starts with 4, its low nibble holds part of the address, and the whole second byte holds the rest.

Details: Register and Jump Instructions

NOP: No Operation

Syntax: NOP. Byte: 00. Cycles: 1. Carry: not changed.

Does nothing, and moves on to the next instruction. It is useful for wasting a little time or for leaving room to patch a program later.

JCN: Jump Conditional

Syntax: JCN condition, address. Bytes: 1c aa, where c is the condition and aa is the low 8 bits of the address. Cycles: 2. Carry: not changed.

Tests a condition, and jumps if it is true. The condition is a 4-bit number made by adding together the tests you want:

JCN condition bits
Bit valueMeaning
1True if the TEST input pin is 0.
2True if C is 1.
4True if A is 0.
8Turn the whole result around, so jump when the tests are false.

If more than one of the bits for 1, 2 and 4 is set, the jump happens when any one of them is true. Adding 8 then reverses that, so the jump happens only when all of them are false. Condition 0 never jumps, and condition 8 always jumps.

This assembler also accepts names for the common conditions:

JCN condition names
NameValue Jumps when
TZ or T01The TEST pin is 0
TN or T19The TEST pin is 1
C1, CY or C2C is 1
C0 or NC10C is 0
AZ or Z4A is 0
AN or NZ12A is not 0

The address is only 8 bits, so the jump stays in the current 256-byte ROM page. The page is the one holding the instruction after the JCN. If a JCN sits in the last two bytes of a page, it jumps into the next page. The assembler reports an error if the target is in a different page.

Example: JCN AN, loop jumps to loop if A is not 0.

FIM: Fetch Immediate

Syntax: FIM Pp, data. Bytes: 2(2p) dd, so 20 for P0, 22 for P1, and so on up to 2E for P7, followed by the data byte. Cycles: 2. Carry: not changed.

Loads an 8-bit value into a register pair. The high nibble goes into the even register and the low nibble goes into the odd one.

Example: FIM P2, 0x3C sets R4 to 3 and R5 to 12.

SRC: Send Register Control

Syntax: SRC Pp. Byte: 2(2p+1), so 21 for P0, 23 for P1, up to 2F for P7. Cycles: 1. Carry: not changed.

Sends the byte in a register pair to the RAM and ROM chips as an address. Every following RAM and port instruction uses it, until the next SRC. For RAM, the top 2 bits pick the chip, the next 2 bits pick the RAM register, and the low 4 bits pick the character. For ROM ports, the high nibble picks the port.

Example: with P1 holding hex 35, SRC P1 selects RAM chip 0, register 3, character 5, and ROM port 3.

FIN: Fetch Indirect

Syntax: FIN Pp. Byte: 3(2p), so 30, 32, up to 3E. Cycles: 2. Carry: not changed.

Reads a byte from ROM and loads it into pair Pp. The address always comes from pair P0. It is an 8-bit address within the current page, the page that holds the next instruction. This is how a 4004 program reads tables and text stored in ROM.

Example: with P0 holding hex 40, FIN P3 reads the ROM byte at hex 040 (if the FIN is in page 0) into R6 and R7.

JIN: Jump Indirect

Syntax: JIN Pp. Byte: 3(2p+1), so 31, 33, up to 3F. Cycles: 1. Carry: not changed.

Jumps to the 8-bit address held in a register pair, within the current page. Programs use it to jump to one of several places worked out at run time, such as a menu of key handlers.

Example: with P1 holding hex 20, JIN P1 jumps to hex 020 (if the JIN is in page 0).

JUN: Jump Unconditional

Syntax: JUN address. Bytes: 4a aa, where the three hex digits a, a and a are the 12-bit address. Cycles: 2. Carry: not changed.

Always jumps, and can reach any address in ROM.

Example: JUN 0x123 assembles to 41 23. The idiom done: JUN done loops forever, which the emulator treats as a halt.

JMS: Jump to Subroutine

Syntax: JMS address. Bytes: 5a aa. Cycles: 2. Carry: not changed.

Saves the address of the next instruction on the chip's stack, then jumps to the subroutine. BBL returns. The stack only holds 3 return addresses. A fourth nested JMS overwrites the oldest one, so the outermost return will go to the wrong place.

Example: JMS load8 calls the subroutine at the label load8.

INC: Increment Register

Syntax: INC Rr. Byte: 6r. Cycles: 1. Carry: not changed.

Adds 1 to a register. 15 wraps round to 0. The carry is not touched, which makes INC safe to use in the middle of a multi-digit addition.

Example: INC R3 is byte 63.

ISZ: Increment and Skip if Zero

Syntax: ISZ Rr, address. Bytes: 7r aa. Cycles: 2. Carry: not changed.

Adds 1 to a register. If the result is not 0, it jumps to the address, within the current page. If the result is 0, it goes on to the next instruction. It is the 4004's loop counter. To repeat a loop n times, set the register to 16 minus n first.

Example: with R6 set to 8, loop: ... ISZ R6, loop runs the loop 8 times.

ADD: Add Register

Syntax: ADD Rr. Byte: 8r. Cycles: 1. Carry: set if the sum is more than 15, otherwise cleared.

A becomes A plus Rr plus C. Because the carry is added in, a chain of ADD instructions can add numbers longer than 4 bits. Use CLC before the first one.

Example: with A at 9, R2 at 8 and C at 0, ADD R2 leaves A at 1 and C at 1, meaning 17.

SUB: Subtract Register

Syntax: SUB Rr. Byte: 9r. Cycles: 1. Carry: set if there was no borrow, cleared if there was a borrow.

A becomes A minus Rr minus the borrow. The 4004 does this by adding the complement of Rr and the complement of C. That means the carry works backwards for subtraction. C at 0 means no borrow in, and C at 1 after the SUB means no borrow out. Use CLC before the first SUB. Between the digits of a longer subtraction, use CMC to turn the borrow-out into the borrow-in the next SUB expects.

Example: with A at 3, R0 at 5 and C at 0, SUB R0 leaves A at 14 and C at 0. In 4 bits, 14 is minus 2, and C at 0 means there was a borrow.

LD: Load Register into Accumulator

Syntax: LD Rr. Byte: Ar. Cycles: 1. Carry: not changed.

Copies a register into A. The register keeps its value.

Example: LD R4 is byte A4.

XCH: Exchange Register and Accumulator

Syntax: XCH Rr. Byte: Br. Cycles: 1. Carry: not changed.

Swaps A and a register. There is no instruction that stores A in a register without swapping, so XCH is also how you save A. The pair LDM d then XCH Rr is the usual way to put a value in a register.

Example: LDM 8 then XCH R6 sets R6 to 8.

BBL: Branch Back and Load

Syntax: BBL d. Byte: Cd. Cycles: 1. Carry: not changed.

Returns from a subroutine, to the address saved by the last JMS, and loads d into A. Subroutines often use d to report a result, such as 0 for success.

Example: BBL 0 is byte C0.

LDM: Load Data to Accumulator

Syntax: LDM d. Byte: Dd. Cycles: 1. Carry: not changed.

Loads the value d, 0 to 15, into A.

Example: LDM 5 is byte D5.

Details: RAM and Port Instructions

All of these are one byte and take 1 cycle. Before you use them, pick the bank with DCL, if it is not already set, and the character or port with SRC.

WRM: Write Main Memory

Byte: E0. Carry: not changed.

Writes A into the selected RAM character.

Example: SRC P1 then WRM stores A at the address in P1.

WMP: Write RAM Port

Byte: E1. Carry: not changed.

Writes A to the 4-bit output port of the selected RAM chip. Each 4002 RAM chip has one output port. Real systems used these for things like lights and printer hammers.

WRR: Write ROM Port

Byte: E2. Carry: not changed.

Writes A to the I/O port of the selected ROM chip, given by the high nibble of the last SRC address. With the emulator's --console option, two WRR writes to the console port make one printed character, high nibble first.

WPM: Write Program Memory

Byte: E3. Carry: not changed.

On a real system, this wrote to program RAM through extra 4008 and 4009 chips, which let development systems load programs. This emulator does not have those chips, so WPM does nothing.

WR0, WR1, WR2 and WR3: Write Status Character

Bytes: E4, E5, E6 and E7. Carry: not changed.

Writes A into status character 0, 1, 2 or 3 of the selected RAM register. Each RAM register has these 4 extra characters besides its 16 main ones. Calculators kept things like the sign and decimal point there. Only the chip and register parts of the SRC address matter. The character part is ignored.

SBM: Subtract Main Memory

Byte: E8. Carry: set if no borrow, cleared if there was a borrow.

A becomes A minus the selected RAM character minus the borrow. The carry works backwards, exactly as for SUB.

RDM: Read Main Memory

Byte: E9. Carry: not changed.

Reads the selected RAM character into A.

RDR: Read ROM Port

Byte: EA. Carry: not changed.

Reads the I/O port of the selected ROM chip into A. In the emulator, set the value a port returns with --rom-in PORT=VALUE, or with the debugger's in command.

ADM: Add Main Memory

Byte: EB. Carry: set if the sum is more than 15, otherwise cleared.

A becomes A plus the selected RAM character plus C. Follow it with DAA to add decimal digits.

RD0, RD1, RD2 and RD3: Read Status Character

Bytes: EC, ED, EE and EF. Carry: not changed.

Reads status character 0, 1, 2 or 3 of the selected RAM register into A.

Details: Accumulator Instructions

All of these are one byte, take 1 cycle and have no operand.

CLB: Clear Both

Byte: F0. Sets A to 0 and C to 0.

CLC: Clear Carry

Byte: F1. Sets C to 0. A is not changed. Use it before the first ADD, ADM, SUB or SBM of a calculation.

IAC: Increment Accumulator

Byte: F2. Adds 1 to A. If A was 15, it wraps to 0 and C is set. Otherwise C is cleared.

CMC: Complement Carry

Byte: F3. Flips C, from 0 to 1 or from 1 to 0. Useful between the steps of a multi-digit subtraction.

CMA: Complement Accumulator

Byte: F4. Flips every bit of A, so A becomes 15 minus A. For example, 5 becomes 10. C is not changed.

RAL: Rotate Accumulator Left

Byte: F5. Shifts the bits of A one place left. The old C goes into the lowest bit, and the old highest bit of A goes into C. Rotating left doubles a number, with the carry as a fifth bit.

Example: A at binary 1001 and C at 0 gives A at binary 0010 and C at 1.

RAR: Rotate Accumulator Right

Byte: F6. Shifts the bits of A one place right. The old C goes into the highest bit, and the old lowest bit of A goes into C.

Example: A at binary 1001 and C at 1 gives A at binary 1100 and C at 1.

TCC: Transmit Carry and Clear

Byte: F7. Sets A to the value of C, 0 or 1, then sets C to 0. Use it to save a final carry as a digit.

DAC: Decrement Accumulator

Byte: F8. Subtracts 1 from A. If A was 0, it wraps to 15 and C is cleared, meaning there was a borrow. Otherwise C is set. The 4004 has no instruction to take 1 from a register, so programs use LD, DAC, then XCH.

TCS: Transfer Carry Subtract

Byte: F9. Sets A to 10 if C is 1, or to 9 if C is 0, then sets C to 0. It exists to help decimal subtraction. It gives the value to subtract a digit from when working out the tens' complement, which turns a subtraction into an addition.

STC: Set Carry

Byte: FA. Sets C to 1. A is not changed.

DAA: Decimal Adjust Accumulator

Byte: FB.

Fixes up A after adding two decimal digits. If A is more than 9, or C is 1, it adds 6 to A. If that goes past 15, C is set. DAA never clears C. If C was already 1, it stays 1.

Example: 6 plus 8 with ADM gives A at 14 and C at 0. DAA adds 6 to get 20, which leaves A at 4 and C at 1. That is 14 in decimal. Lesson 3 explains this step by step.

KBP: Keyboard Process

Byte: FC. C is not changed.

Turns a keyboard bit pattern into a key number. A keyboard row where exactly one key is pressed gives a value with exactly one bit set. KBP turns that into the number of the key. If no key or more than one key is pressed, the result is 15, meaning error.

KBP results
A beforeA after

DCL: Designate Command Line

Byte: FD. C is not changed.

Selects a RAM bank using the low 3 bits of A, so banks 0 to 7. Every RAM instruction after it uses that bank, until the next DCL. On a real board the value drove the chip's command lines. This emulator assumes a decoder that turns each value into one bank. The chip starts with bank 0 selected.

Example: LDM 2 then DCL selects bank 2.

FE and FF: Unused

These two bytes are not instructions. If the emulator tries to run one, it stops with an illegal opcode error. That usually means the program has jumped into its own data.
